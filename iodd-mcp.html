Create IODDs with your coding assistant.

A local MCP server and command-line tool for IO-Link device descriptions. Create a project, edit parameters and process data, check it, and export XML, a ZIP package and a C firmware mapping. The browser editor opens the same project files.

Import a working stack example

Download the switching-sensor IODD package or counter/button/LED IODD package. Open the ZIP in the editor, CLI or MCP. Each describes its corresponding released iolinki firmware example, with matching identity, parameter indexes and process-data bits.

Start locally

Install Node.js 22 or newer, download and extract the source bundle, then run these commands from its iodd-tools directory: 

npm ci
node tools/iodd/cli.mjs --help
node tools/iodd/mcp.mjs

Add the server to your MCP client configuration using the absolute path where you extracted it: 

{
  "mcpServers": {
    "iolinki-iodd": {
      "command": "node",
      "args": ["/absolute/path/iodd-tools/tools/iodd/mcp.mjs"]
    }
  }
}

Try an authoring task

Copy this into your connected coding assistant:

Create a switching-sensor IODD. Inspect its parameters and process fields. Rename the product to “Distance Switch”. Ask me for my assigned vendor and device IDs. Keep its threshold and hysteresis parameters, add an English diagnostic event, run validation, and export the project, XML, ZIP and firmware mapping header.

CLI Repeatable generation, project edits, package exports and checks in development scripts.

Advanced authoring

Create a new device or start from a working example. Edit complex datatypes and conditional layouts in the document tree. Save a manufacturer project as a reusable template, and import selected elements with their text and datatype dependencies.

Load published IO-Link profile snippet packs, choose a profile variant and fill its template bindings. Configure wired or wireless communication and declarative validation rules. Create and inspect IOLFW firmware packages containing a binary and optional resources, with CRC and SHA-256 verification.

The browser can search the public IODD Finder and import approved packages. Project contents stay local; only an explicit Finder search or download uses the read-only catalog service.

Validate and keep firmware aligned

Basic checks cover model references, parameter ranges, process-field overlaps and CRC. Configure a locally installed official XSD or official checker to record its result separately. Generated C mappings use the IODD's parameter indexes and process-bit offsets. The matching firmware example and LabWired recipes provide the next development steps.

Projects stay in your browser or local MCP process. Export project JSON to save your work and reopen it in either interface. The MCP server uses local stdio; this download is ready to run with your client.
