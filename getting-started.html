Try the host stack

A repeatable Linux evaluation before a hardware integration.

Getting startedHardware & IDEsValidationFAQ & licensing

1. Build a pinned release

Use Linux with Git, a C99 compiler and CMake 3.20 or newer. These commands use the published v2.0.0 release, so your starting point is reproducible. No IO-Link board is required.

git clone --branch v2.0.0 --depth 1 https://github.com/w1ne/iolinki.git
cd iolinki
cmake -S . -B build -DIOLINK_PLATFORM=LINUX -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure

2. Read the result

The host build and all 22 CTest targets passed with GCC 13 on Linux on 1 October 2026. Expect CTest to report 100% tests passed. A compiler or test failure on your machine is a useful issue report; include the tag, operating system, compiler version, command and full error output.

These tests exercise software protocol behavior. Passing them does not establish physical transceiver timing, a working MCU board, interoperability with a commercial master, or certification. The validation page separates those checks.

3. Run the counter, button and LED example

The new reference device needs no board or serial peer. This recipe pins its exact source commit separately from the v2.0.0 baseline above.

git fetch origin 1bc8d9c798efcea782f5fe79e963afc27f74eac8
git checkout --detach 1bc8d9c798efcea782f5fe79e963afc27f74eac8
cmake -S . -B build-reference -DIOLINK_PLATFORM=LINUX -DBUILD_TESTING=ON
cmake --build build-reference --parallel 4
./build-reference/examples/reference_device/reference_device_demo
ctest --test-dir build-reference --output-on-failure

Expect SIMULATION PASS after 100 checked cyclic frame exchanges. The example checks counter data, LED commands and checksums, a local application-tag readback, and a queued button event. All 27 CTest targets passed for this commit. It does not demonstrate a physical LED, wire-level ISDU, event acknowledgement or persistent storage. Read the payload and integration guide.

4. Inspect the existing examples

  • Host demo: build/examples/host_demo/host_demo requires a TTY path and uses the virtual PHY transport. Running it without arguments prints its usage and exits with a nonzero status. A running state machine needs a compatible peer; this is not a ready-made commercial-master connection.
  • Simple device: source and example IODD files are available. Its application entry point is a placeholder; a successful build does not make it a functional physical device.
  • Zephyr application: includes a Nucleo-L476RG UART overlay. Fresh board-build and physical-master evidence are pending.

5. Choose an integration path

Compare the exact board and IDE status before buying hardware. The STM32G0 example includes GCC firmware and native IAR project sources; IAR compilation remains unverified. STM32U5/Zephyr and ESP32/ESP-IDF projects are planned. UART source availability alone does not establish a complete TIOL112 or L6362A integration.

For a proprietary product, review commercial terms. For GPL evaluation, read the release license and consider your intended use and distribution. Source and these instructions are public; no email registration is needed.
