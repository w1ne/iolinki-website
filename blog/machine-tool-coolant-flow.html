Coolant flow on a machine tool: teach the normal flow, switch on a percentage

If the coolant stops, the tool and the part pay for it within seconds. A flow sensor in the coolant line stops the cycle before that happens and reports the coolant temperature too.

11 October 2026 · Andrii Shylenko

The job

A machine tool pumps coolant to the cutting zone. A clogged filter, a kinked hose or a worn pump reduces the flow without any alarm from the pump itself. We want the machine to know that coolant really flows, and we want the coolant temperature in the same device.

The sensor

We used the ifm SA5000, a calorimetric flow sensor with a 45 mm probe and an M18 x 1.5 process connection. The datasheet: liquids 0.04 to 3 m/s, media water, glycol solutions, air and oils, medium temperature −20 to 90 °C, pressure rating 100 bar. It also measures the medium temperature, −20 to 90 °C with 0.2 °C resolution.

Coolant emulsion is not on the media list. For that case ifm recommends relative mode: you run the machine at its normal flow and teach it, and the sensor then shows flow as 0 to 100 % of the taught high flow. Relative mode is the factory setting, device ID 533 in the datasheet.

The setting, checked

We want “flow OK” while the flow is at 60 % of normal or more, and we want it to drop at 50 %. The IODD allows SP1 from 5 to 100 % and rP1 from 0 to 96 %, so 60 and 50 fit, and rP1 is below SP1.

Two datasheet numbers belong in the PLC program, not in the sensor. The power-on delay is 10 s, so ignore the flow signal for the first 10 s after the sensor gets power. The response time for water is 0.5 s (glycol 0.8 s, oil 1.8 s). A flow loss reaches the PLC that much later.

Master, port and cable

This machine's control runs EtherCAT, so we used a Beckhoff EP6224-2022, a 4-port IO-Link box. Beckhoff gives 1.4 A sensor supply per port and 4 A for all four. The SA5000 draws less than 100 mA and needs a class A port. The route is 6.3 m, so the order has a 10 m M12 cable.

The datasheet accuracy figure assumes 1.5 m of straight pipe before the sensor in a DN25 line. In relative mode you teach in place, so the exact number matters less, but keep the sensor away from bends and valves where you can.

Run mode

Run mode varies the flow. OUT1 switches on above 60 % and drops at 50 %. The 32-bit process data carries the flow in bits 16 to 31 in %, the temperature in bits 2 to 15 at 0.1 °C per count, and OUT2 and OUT1 in bits 1 and 0. In the screenshot the master reads 00 4B 03 71: flow 0x004B = 75 %, temperature 0x0371 shifted right by two = 220, that is 22.0 °C, and OUT1 on. The simulated temperature is a fixed room value; on the machine you see your coolant.

The report flags the operating mode as a data gap: the studio has no ISDU index for it. Relative is the factory setting, so a new sensor needs no write. If someone changed it, set it back on the sensor. The teach of the normal flow is done on the running machine at commissioning; the commissioning file cannot do that part.
